Features

Built for the OPML you already have.

Three columns

Feeds → items → article

The reader shape that worked in 2005 and still works. All three visible at once; no back buttons.

.opml in / out

Your file, your subscriptions

One OPML file per window. Round-trips with NetNewsWire, Feedly, miniflux — take it elsewhere any time.

RSS · Atom · JSON Feed

One reader, every format

feed-rs under the hood, so the parser doesn't care which dialect the feed speaks.

ETag · Last-Modified

Polite fetching

304s on unchanged feeds. No re-parsing what already arrived. 15s timeout, no redirect loops.

Sanitized HTML

Article bodies render, scripts don't

ammonia strips inline JS, iframes, on-handlers. The feed's text + images + links, nothing else.

Tauri · Rust

Native Linux

Small binary, AppImage and .deb, real file associations, in-app updater. No Electron.

Principles

What this isn't.

No accounts, no cloud. Your subscriptions live in an OPML on your disk. There's nothing to log into.
No daemon. Closed app, zero network activity. Feeds refresh on launch or when you ask.
No bridges. Fever, Greader, Inoreader, Miniflux APIs — none. Standard OPML and HTTP, nothing else.
No smart folders. No filtering rules, no "read later" integrations. Read it or don't.
Install

Two files. One minute.

Both formats ship the same binary and register .opml as an associated file type so opens land in this app by default.

Or build from source: pnpm install && pnpm tauri build.

AppImage · any Linux

# download
curl -LO https://github.com/krill-software/rss-reader/releases/download/v0.2.1/RSS.Reader_0.2.1_amd64.AppImage

# make executable & run
chmod +x RSS.Reader_0.2.1_amd64.AppImage
./RSS.Reader_0.2.1_amd64.AppImage feeds.opml

Debian / Ubuntu

sudo dpkg -i RSS.Reader_0.2.1_amd64.deb
